# ColBench (SWEET-RL) × ppol — backend/code track

Integration of [ColBench](https://github.com/facebookresearch/sweet_rl) (Zhou et
al., 2025, [arXiv:2503.15478](https://arxiv.org/abs/2503.15478)) with ppol. Like
`examples/tau2bench/` and `examples/wildchat/`, this is a self-contained
`EpisodeRunner` plus its driver — not part of the installed wheel.

## Why ColBench fits ppol

In ColBench's backend-programming task an LLM **agent** must write a personalized
Python function. It can't see the requirements; it must extract them over ≤10
turns from a **simulated human collaborator** that privately holds the reference
solution. Success = fraction of hidden unit tests the agent's final code passes.

That simulated human is exactly what ppol overlays:

- it produces the `role=="user"` turns (the party ppol fingerprints),
- in vanilla ColBench it is deterministic (temperature 0), capped at two
  sentences, and purely cooperative — the homogeneous, over-compliant simulator
  ppol exists to diversify.

`ColBenchRunner` injects a persona into the human simulator's system prompt and
leaves the task facts (problem, hidden solution, tests, reward) untouched.

Only the **code** track is implemented — it is CPU-friendly (local sandboxed
unit-test execution, any LiteLLM model for agent + sim). The frontend/html track
needs Selenium + Firefox + a vision sim + CLIP and is out of scope.

## Data

- **Tasks** — `facebook/collaborative_agent_bench` (`backend_tasks/{train,test}.jsonl`,
  10k each). Each record: `problem_description`, `ground_truth` (reference fn,
  doubles as the sim's hidden info), `test_cases` (hidden unit tests).
  Auto-downloaded from the HF Hub on first use.
- **Human reference (positive class)** — real developer turns from
  [`SALT-NLP/SWE-chat`](https://huggingface.co/datasets/SALT-NLP/SWE-chat): the
  `role=="user"`, `is_conversational` turns, grouped per session, with
  auto-continuation summaries and giant pastes filtered out. See
  `swe_chat_reference.py`. Only `conversations.parquet` (~1.3 GB) is downloaded.
- **Baseline (negative class)** — generated by running this runner with **no
  persona**; the vanilla ColBench simulator *is* the "not human-like" anchor.

## Setup

```bash
pip install -e .            # ppol
pip install pandas huggingface_hub   # for data + SWE-chat reference
export OPENROUTER_API_KEY=...        # or OPENAI/ANTHROPIC/GEMINI
```

Nothing from the SWEET-RL repo needs installing. The pieces we reuse are
vendored: the official prompt files in `prompts/` (copied **verbatim** — see
`prompts/README.md`) and the sandboxed correctness check in `runner.py`.

## Run

Full pipeline:

```bash
python examples/colbench/run_pipeline.py \
    --steps reference,baseline,discriminator,evolve \
    --train-pool 1000 --val-size 20 --iterations 200
```

Steps (`--steps` accepts any comma-separated subset, or `all`):

| step | what it does |
|---|---|
| `reference` | build the SWE-chat human reference |
| `baseline` | persona-free ColBench episodes (discriminator negatives) |
| `discriminator` | RF: SWE-chat human vs. vanilla ColBench sim |
| `evolve` | evolve the persona generator `G(c, D, N)` |

Useful flags: `--train-pool`, `--val-size`, `--max-sessions` (SWE-chat sessions
for the reference), `--iterations`, `--n-workers`, `--agent-model`,
`--human-sim-model`, `--output-dir`.

Held-out evaluation is separate:

```bash
python examples/colbench/benchmark.py --n-personas 10
```

## Python API

```python
import sys; sys.path.insert(0, "examples/colbench")
from runner import ColBenchRunner

runner = ColBenchRunner(num_tasks=200, agent_model="openrouter/google/gemma-4-31b-it")
task = runner.get_tasks()[0]

# persona-free (baseline behavior)
print(runner.run_episode(task).reward)

# with a persona overlay
persona = "You are terse and impatient; answer in as few words as possible."
r = runner.run_episode(task, persona_policy=persona)
print(r.reward, r.success, r.n_turns)
```

## Fidelity to official ColBench

`runner.py` reproduces the official `HumanInteractionEnv` / `VLLMAgent`
mechanism as closely as a LiteLLM reimplementation allows:

- **Verbatim prompts** — `prompts/*.txt` are byte-identical to the official
  files (`prompts/README.md`).
- **Human simulator** — re-prompted statelessly each turn exactly as
  `HumanInteractionEnv.invoke_model`: system `"You are a helpful assistant."`,
  the whole `human_simulator_code_prompt.txt` (with the dialogue rendered by a
  verbatim port of `str_dialogue_history`) as one user message, **temperature
  0**, reply truncated to **400 chars**.
- **Agent** — prompted exactly as `VLLMAgent.get_action`: chat with
  `system = llm_agent_code_prompt.txt` followed by the dialogue history as
  messages; sampling at temperature 1.0, 1024 max tokens.
- **Parsing** — the same `OUTPUT:` / `I WANT TO ANSWER:` handling as
  `HumanInteractionEnv.step`.
- **Reward** — the sandboxed correctness check ported from
  `sweet_rl/utils/code_utils.py` (subprocess isolation, 2 s per-test timeout,
  import/IO blocklist). `success` = all hidden tests pass.

**The one ppol-specific addition:** the persona block is appended to the human
simulator's prompt (via `inject_persona_into_system_prompt`) — nothing else in
the loop, reward, or task facts changes. Because the official prompt keeps its
"answer IN TWO SENTENCES" instruction, personas shape *tone, uncertainty,
cooperativeness, and phrasing* within that length cap rather than overriding
verbosity. The persona-free baseline is therefore the faithful vanilla ColBench
simulator (deterministic, terse, cooperative) — the intended "not human-like"
anchor for the discriminator.
